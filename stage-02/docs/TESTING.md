# Фактическая проверка этапа 2

Дата: 2026-10-11. Fedora 44, PostgreSQL **18.6**, XeLaTeX/TeX Live; локальный кластер `/tmp/labreserve-stage02-pg`, Unix-сокет `/tmp`, порт 55432, TCP отключён.
База: строго `labreserve_stage02_test`. Пользовательские БД не использовались.

## Выполненные проверки

1. Создание отдельной БД через `create_database.sql`.
2. Транзакционная установка DDL, функций, триггеров и индексов через `install.sql`.
3. Загрузка воспроизводимых демонстрационных данных через `05_demo.sql`.
4. **60 из 60** утверждающих SQL-тестов: корректные операции, SQLSTATE запрещённых действий, история, роли, допуски, альтернативы, точный union простоя, закрытие работы.
5. **5 из 5** сценариев с двумя реальными psql-соединениями; соединение A удерживало блокировку, соединение B начинало операцию во время ожидания A. Синхронизация через pg_stat_activity/PgSleep, без предположения, что процессы «наверняка» пересеклись.
6. `EXPLAIN (ANALYZE,BUFFERS)` на 1 000 дополнительных единицах и 20 000 подтверждённых непересекающихся бронях; данные внесены в BEGIN и удалены ROLLBACK.
7. Очистка только учебной схемы, создание с нуля, повторная загрузка данных и повтор всех SQL-утверждений. Дополнительно реально выполнены DROP DATABASE и CREATE DATABASE для созданной нами labreserve_stage02_test; после полного пересоздания БД все 60 утверждений снова прошли.
8. CSV-выгрузка аналитики и экспорт модели из системного каталога.
9. Сборка диаграмм и отчёта XeLaTeX; визуальная проверка страниц, таблиц и диаграмм (результаты QA — `VISUAL_QA.md`).
10. Сравнение SHA-256 всех файлов stage-01 до и после работы.

Тесты откатываются; роль NOLOGIN для проверки прав тоже создаётся и откатывается в той же транзакции.
Конкурентные тесты фиксируют результат, затем отменяют только свои тестовые брони; общий runner далее пересоздаёт учебную схему и восстанавливает чистые демонстрационные данные.
Скрипты очистки не принимают произвольное имя БД. `drop_database.sql` удаляет только явно зарезервированную учебную БД и не использует FORCE.

## Препятствия и фактические ошибки при разработке

- Песочница запрещала создание и подключение Unix-сокета (`Operation not permitted`). Для запуска и проверки отдельного кластера использовано разрешённое выполнение вне песочницы.
- `btree_gist` отсутствовал в системной установке. RPM `postgresql-contrib-18.6-1.fc44.x86_64` загружен и распакован в `/tmp`; PostgreSQL 18 `extension_control_path` направлен на временный каталог, module_pathname — на извлечённую библиотеку. Системная установка PostgreSQL не изменялась.
- Первая установка нашла пропущенную закрывающую скобку домена time_window; ошибка исправлена, транзакция установки была откатана.
- В тесте T30 начальная бронь захватывала уже завершённую поломку; БД правильно отклонила историческое пересечение. Исправлен тест, а не правило БД.
- В тесте T38 оборудование уже было восстановлено, поэтому ожидаемого отказа не было. Тест перенесён на действительно неисправное оборудование.
- При визуальной проверке первой версии даталогической диаграммы стрелки перекрывали текст таблиц. Узлы переставлены, подписи FK вынесены в отдельный перечень; исходники и PDF пересобраны.

SQL не объявлялся работоспособным до реального успешного выполнения. Полный runner: `sql/scripts/run_checks.sh`.

После завершения проверок временный PostgreSQL-сервер остановлен. Учебная БД остаётся в каталоге кластера /tmp; окончательные SQL и результаты сохранены в stage-02 и не зависят от сохранности /tmp.
Полное удаление/создание БД проверено отдельно; после него 60/60 утверждений также прошли. Сводка окончательной проверки: FINAL_CHECK.txt.
