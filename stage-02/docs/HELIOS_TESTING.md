# Проверка поддержки LOCAL и HELIOS

Дата: 2026-10-13. Реальное развёртывание на университетском сервере выполнено и проверено.

## Матрица испытаний

| Окружение | Права роли | Пересечения | Результат |
|---|---|---|---|
| Локальный PostgreSQL 18.6, симуляция studs.s466088 | Нет SUPERUSER, CREATEROLE, CREATE в базе | Сериализация + BEFORE-проверка, без btree_gist | 57/57 общих бизнес-тестов, 18/18 smoke, 10/10 конкурентных сценариев |
| Локальный PostgreSQL 16.15 (кешированный Alpine-образ), симуляция studs.s466088 | Те же ограничения | EXCLUDE, btree_gist в отдельной gist_support | 57/57 общих бизнес-тестов, 18/18 smoke, 10/10 конкурентных сценариев |
| LOCAL, PostgreSQL 16.15, отдельная labreserve_stage02_test.labreserve | Администратор одноразового кластера | Исходный EXCLUDE | Полный неизменённый run_checks.sh: 60/60, 5/5 конкуренция, EXPLAIN, 60/60 после пересоздания |
| Реальный Helios, PostgreSQL 18.3, pg/studs/s466088 | Нет SUPERUSER, CREATEROLE, CREATE в базе | Trigger-вариант, btree_gist отсутствует | 57/57 бизнес, 18/18 smoke, 10/10 конкуренция, 7/7 адаптер; повтор установки безопасен |

Исходный LOCAL на Fedora 18.6 ранее прошёл полный набор (см. `TESTING.md`). В этой сессии полный runner повторно выполнен на 16.15; на 18.6 выполнен набор адаптера **без** расширения. Fedora contrib в текущем окружении отсутствует, временные пакеты прежней сессии не сохранились, загрузка RPM была недоступна по сети. Полный повтор LOCAL на 18.6 в этой сессии не заявляется. Общие SQL-исходники LOCAL, исходные тесты и runner не изменены.

Контейнер 16.15 запускался из уже имеющегося образа без сети и TCP; доступ — через временный Unix-сокет. PostgreSQL 18.6 также работал в отдельном /tmp-кластере без TCP. Общие/пользовательские базы Fedora не использовались. Тестовые серверы остановлены по завершении проверки.

## Конкурентные пробы

В обоих вариантах прошли:

1. HC01 — одинаковые API-брони: вторая 23P01 при READ COMMITTED.
2. HC02 — прямые INSERT: вторая 23P01 при READ COMMITTED.
3. HC03 — API с устаревшим снимком REPEATABLE READ: 40001.
4. HC04 — прямой INSERT с устаревшим снимком: 40001.
5. HC05 — прямой UPDATE интервала в занятой области: 23P01.
6. HC06 — прямой UPDATE с устаревшим снимком: 40001.
7. HC07 — ТО фиксируется перед прямой бронью: 23514.
8. HC08 — бронь фиксируется перед ТО: перевод в needs_transfer; пересечений confirmed нет.
9. HC09 — первая бронь откатывается: вторая успешно занимает освобождённый интервал.
10. HC10 — один многострочный INSERT с двумя пересекающимися строками: 23P01, оператор откатан.

Для HC01–HC09 наблюдалось реальное ожидание блокировки второго соединения в pg_stat_activity. После каждой пары проверены отсутствие confirmed/confirmed и confirmed/недоступность пересечений. История собственных проб сохранена; записи отменены/архивированы по штатным операциям.

## Безопасность установки

Семь интеграционных проверок прошли на одноразовом 16.15-кластере:

- I01 — повторный install не изменяет количество строк приложения, чужие данные, ACL схемы/таблицы и определение чужой функции.
- I02 — добавленный посторонний lr_-объект сохраняется, установщик отказывает.
- I03 — отключённый бизнес-триггер обнаружен, установщик отказывает.
- I04 — изменённый хеш версии не допускает перезапись.
- I07 — объекты без манифеста не перезаписываются.
- I05 — неверные база/пользователь отклоняются shell-проверкой; SQL preflight отдельно возвращает код 3 при ошибке.
- I06 — после восстановления исключительно тестовых изменений исходная установка проходит проверку, данные и чужие объекты совпадают с контрольным снимком.

Дополнительно семь автономных тестов генератора проверяют сохранение actor_id, сообщений/комментариев, обработку динамического SQL и вложенного экранирования, отсутствие переименования неизвестных объектов, полный состав обеих моделей, отказ при несовпадении ожидаемого исходного фрагмента и детерминированную сборку без CREATEROLE.

При проверке отказов обнаружено, что psql игнорирует числовой аргумент `\quit`. Новые Helios-шаблоны используют RAISE EXCEPTION и ON_ERROR_STOP; отказ не сопровождается ложным сообщением об успешной установке.

## Реальное развёртывание на Helios

Установка завершена 2026-10-13 в studs.s466088 на pg (PostgreSQL 18.3, FreeBSD); часовой пояс сеанса Europe/Moscow. Python 3.11 вызывается как python3.11 через новый launcher. Рабочий каталог — ~/labreserve-stage02-20261013. Исходный хеш установки: 4e8d1ab392deb1a9dd7421b32eeee882bf6fa613f17297ba29744456c8a50fed.

На реальном сервере повторены все 57 общих бизнес-тестов, 18 smoke и 10 конкурентных проб, а также семь автономных тестов генератора. Прямые INSERT/UPDATE, READ COMMITTED и REPEATABLE READ дали ожидаемые SQLSTATE. Проверка demo.sql прошла, пересекающихся confirmed-броней нет. Демонстрационные данные загружены один раз; пробы отменены/архивированы по штатным операциям с сохранением их аудита.

Повторный install завершился успешно, seed пропущен. Количество пользователей, оборудования, броней и аудита до/после совпало. Отдельный скрипт shared_schema_snapshot.sql сохранил каталог посторонних объектов до/после: 42 отношения и шесть функций, их определения, столбцы, ограничения, триггеры, владельцы и ACL не изменились. SHA-256 обоих снимков: 221619736f33cb06307455ccbdbdf861e883c43aec3a9bfd88bb83a157d1b442. Полные снимки остаются в приватном рабочем каталоге; в Git сохранён только результат сравнения, без чужих данных.

Свидетельства реального сервера: helios-remote-results.json, helios-remote-install.txt, helios-remote-business.txt, helios-remote-checks.txt, helios-remote-repeat.txt. Локальные административные I01–I07 на университетском сервере не запускались.
